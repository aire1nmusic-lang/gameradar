## What the host is for

GameScout's public catalog and permitted aggregates remain in Cloudflare/D1. The private API needs durable transactional storage for accounts, password hashes and sessions, Claims, votes and anti-fraud evidence, GS Coins ledger, test-payment events, copyright claims and audit. The current implementation uses PostgreSQL-specific migrations and transactions. The quoted 4,480.70 ₽ was **only the managed database**, not the whole private API stack.

### Lower-cost Russian-provider candidate — changes the agreed boundary

[Amvera's published plans](https://docs.amvera.ru/general/price.html) list an always-on application at 290 ₽/30 days (0.25 CPU/500 MB/5 GB) and PostgreSQL at another 290 ₽/30 days (0.25 CPU/500 MB/5 GB): **580 ₽/30 days minimum list-price sum**, before excess storage or other services. A more plausible staging starting point is application 490 ₽ (0.5 CPU/1 GB/7 GB) plus PostgreSQL 490 ₽ (0.5 CPU/1 GB/7 GB): **980 ₽/30 days**, still subject to load and migration tests. These are not tested GameScout capacity commitments or account-specific quotes. Amvera [offers a Moscow data region and says its database backups/logs remain in Russia](https://amvera.ru/managedpostgresql); the exact application region, contract, data flows, security and backup restore must be verified before use. The 290 ₽ database and 290 ₽ application are separately billed; “free backups” do not mean free hosting. [Timeweb's PostgreSQL begins at 790 ₽/month](https://timeweb.cloud/services/postgresql), with application hosting additional.

Moving private data to Amvera or Timeweb **changes the original Yandex Cloud private-data boundary**. The owner has authorized considering a lower-cost Russian provider, but no specific provider or paid deployment has been approved. [The Amvera staging review](amvera-staging-review.md) records the unresolved TLS, ingress-IP, Cron price, retention and restore checks. A Russian server location alone does not establish full personal-data compliance.

The official Compute Cloud [ready configurations](https://yandex.cloud/ru/services/compute) are published as “from” prices, not a quote for this billing account. [Compute pricing](https://yandex.cloud/ru/docs/compute/pricing) and [VPC pricing](https://yandex.cloud/ru/docs/vpc/pricing) explain extra resources. [Managed PostgreSQL pricing](https://yandex.cloud/ru/docs/managed-postgresql/pricing), [YDB and container free tier](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier), [YDB modes](https://yandex.cloud/ru/docs/ydb/concepts/serverless-and-dedicated) and [preemptible VM limits](https://yandex.cloud/ru/docs/compute/concepts/preemptible-vm) support the distinctions above. A preemptible VM can be forcibly stopped within 24 hours, so it is unsuitable as the transactional database host. A one-time introductory grant may offset an initial bill; it is not a recurring free tier.

## Recommendation and gate

Continue locally at 0 ₽ while completing the core. Compare a reproducible Yandex single-VM staging plan with the lower-price Amvera candidate, using the existing PostgreSQL backend. Resolve the Amvera blockers before selecting it. For either provider require a fixed-size disk, encrypted backup and **tested restore**, restricted ingress, secrets, cost alert and explicit shutdown/rollback steps. Before creating a paid resource, show the exact account-specific **total including storage, backup and background jobs** and obtain a monthly spending cap. Do not migrate production data, switch DNS or enable real sales as part of staging. If a future production launch needs higher availability, price and review that separately against measured usage.
