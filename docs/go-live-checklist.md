## 2. Почта с кодами подтверждения

Нужен российский отправитель, иначе возникает передача данных за границу.

1. Зарегистрироваться в Unisender Go и подтвердить домен отправителя `gamescout.online`. Сервис покажет 2–3 записи для DNS (SPF, DKIM, иногда DMARC). **Их вносите вы** в DNS-панели домена.
2. Создать API-ключ, отправитель, например, `GameScout <no-reply@gamescout.online>`.
3. На машине в `deploy/vm/.env` задать:
   ```
   MAIL_DRIVER=unisender
   MAIL_FROM=GameScout <no-reply@gamescout.online>
   UNISENDER_API_KEY=<ключ>
   ```
4. Перезапустить API: `docker compose up -d api`. Отправить тестовое письмо на свой адрес через регистрацию.

## 3. Вход через Google, VK и Яндекс

Google и Discord уже настроены на VM, не заменять приложения или secrets без причины. Для Google есть свидетельство live входа; Discord требует отдельной проверки потока. VK отсутствует в текущем VM-инвентаре; Яндекс отложен владельцем. Ниже справочные callback/config для подключения после выдачи отсутствующих доступов, а не поручение заново создавать всех провайдеров:

| Провайдер | Где создать | Адрес возврата | Переменные в `.env` |
|---|---|---|---|
| Google | console.cloud.google.com → APIs & Services → Credentials → OAuth client (Web) | `https://gamescout.online/api/v1/auth/google/callback` | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` |
| Яндекс | oauth.yandex.ru → Создать приложение → Веб-сервисы, доступ к e-mail не нужен | `https://gamescout.online/api/v1/auth/yandex/callback` | `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` |
| VK ID | id.vk.com → Мои приложения → Веб | `https://gamescout.online/api/v1/auth/vk/callback` | `VK_CLIENT_ID`, при наличии `VK_CLIENT_SECRET` |
| Discord (по желанию) | discord.com/developers/applications → OAuth2 | `https://gamescout.online/api/v1/auth/discord/callback` | `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` |

Запрашиваем минимум: идентификатор, имя, аватар. OAuth-вход ищет аккаунт только по паре «провайдер + его ID». Совпадение email у Google, Discord или VK **не** объединяет аккаунты; привязка другого провайдера требует действующей сессии пользователя, а email подтверждается отдельно. Это соответствует текущему `private-api/app.mjs`. Яндекс OAuth отложен: создание приложения сейчас заблокировано подтверждением через Госуслуги.

Google и Discord — иностранные сервисы. Вход через них не обязателен для запуска: начать можно с почты, Яндекса и VK.

## 4. Публичный HTTPS-адрес приватного API — сделано, осталось переключить маршруты шлюза

Шлюз Yandex должен направлять `/api/v1/auth/*`, `/api/v1/me/*`, голоса, монеты и остальное приватное в контейнер на машине. Заготовка шлюза уже в репозитории (`ru-proxy/yandex/gateway.private.template.yaml`, описание в `docs/yandex-private-gateway.md`).

1. Завести в DNS запись **A** для `priv.gamescout.online` на публичный IP виртуальной машины. Это можно вносить в Cloudflare, режим «только DNS» (серое облако).
2. В `deploy/vm/.env` задать `PRIVATE_API_HOST=priv.gamescout.online`. Caddy сам получит сертификат.
3. В группе безопасности машины открыть 80 и 443 для всех, 22 — только с вашего адреса. Порты 5432 и 8080 не открывать.
4. Проверить с любого компьютера: `https://priv.gamescout.online/api/v1/health` отвечает 200.
5. Только после этого — переключение маршрутов шлюза (делает отдельным шагом Кодекс или я, по вашему подтверждению), и **тогда же** на Cloudflare включается `PUBLIC_ONLY=true`.

Важно: настоящий IP посетителя. Caddy кладёт в заголовок адрес того, кто к нему обратился. Если перед ним стоит шлюз Yandex, там окажется адрес шлюза, и защита от накруток голосов ослабнет. Это проверяется на тестовой среде до включения.
