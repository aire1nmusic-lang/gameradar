# Yandex static HTML candidate — not deployed

`gamescout.online` currently serves static files through Yandex API Gateway and Object Storage. The live gateway template maps unknown paths to `index.html` with HTTP 200, so the Cloudflare Pages 404/prerender checks do **not** prove production SEO. The reviewed candidate is [`gateway.prerender.template.yaml`](../ru-proxy/yandex/gateway.prerender.template.yaml): `/` stays `index.html`, `/assets/*` and `/media/*` stay raw files, exact robots/sitemap/icons stay raw, and other page paths map to `{file}/index.html`. A missing page uses `404.html` with HTTP 404. `/api/*` and `/__gs/health` retain the existing relay integration; this candidate does not cut over private API traffic.

Yandex's [Object Storage extension](https://yandex.cloud/ru/docs/api-gateway/concepts/extensions/object-storage) documents path-parameter object templating and `error_object.statusCode`; [greedy parameters](https://yandex.cloud/en/docs/api-gateway/concepts/extensions/greedy-parameters) cover nested server/world routes. Local tests check the candidate's expected object keys, not Yandex's actual gateway parser or HTTP behavior. The existing gateway spec must be exported before any update.

The staging mirror's `--noindex` option now rewrites **every** HTML object's robots meta tag, because Object Storage does not apply Vercel's `X-Robots-Tag` configuration. It also publishes `robots.txt` with `Disallow: /` and omits the sitemap. This closes a gap in the current staging upload path without touching a cloud resource.

Before a proposed staging change: build from the actual public D1 catalog with `npm run build:catalog -- https://PUBLIC_API_ORIGIN/`; confirm the reconciliation gate passes; assemble the mirror with `node ru-proxy/build.mjs --noindex --out ru-proxy/.deploy-staging`; inspect HTML and object keys; export the current staging gateway specification and bucket object version/list; estimate Object Storage PUT/GET and API Gateway request use under the existing budget. Apply only to a reviewed staging gateway, upload all objects first, then change its spec. Test HTTP status and HTML for `/`, `/catalog`, each game, one server per game, an unknown route, assets, robots, sitemap and API. Confirm staging noindex. A static page absent from the build returns 404 until the next catalog-backed build, so moderation and upload must be coordinated.

Production requires a separate review of the exact gateway diff, current/target URLs, cache behavior and restore command. Roll back by restoring the exported gateway specification and previous bucket objects; do not change production DNS or the private/public API split as part of this candidate. No cloud calls or billable resources were created here.
