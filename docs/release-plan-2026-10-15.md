## Подготовленный путь восстановления приватного входа

VERIFIED: существующий российский API Gateway `gamescout-ru` отдаёт опубликованный сайт из того же Яндекс-бакета и рабочие `/auth/me`, `/people-rating`, `/health`, `/payments/test/config`. Пробный HTTPS-запрос с именем `gamescout.online` и подключением к существующему шлюзу вернул 200 для `/auth/me`, сертификат проверялся штатно. Регистрация и продажи остаются выключены.

Предлагаемый результат: основной домен снова обслуживается существующим Яндекс-шлюзом; сессии, пароли и транзакции проходят российский ingress. Платные ресурсы, новый сервер и перенос базы не нужны. Репозиторий и загрузка в текущий Яндекс-бакет сохраняются.

Перед выполнением нужно отдельно согласовать production DNS (требование AGENTS.md) и получить существующий операторский доступ к соответствующим DNS/custom-domain настройкам. Текущий GitHub ключ не имеет DNS read; нельзя обещать выполнение одним кодовым пушем.

Последовательность после согласования:

1. Снять защищённый снимок точной текущей apex DNS-записи и привязки Worker custom domain; проверить актуальные сборки обоих origin, сертификат и анонимный private API. Не выводить секреты.
2. Подготовить обратное восстановление Worker custom domain `gamescout-emergency-preview` и исходной DNS-записи. Не удалять Worker, Яндекс-бакет, базу или исторические версии.
3. Переключить apex на существующий шлюз `d5d9pl6cgdpfk52duoa2.fovt0b64.apigw.yandexcloud.net` в режиме DNS only, корректно сняв конфликтующую управляемую привязку Worker. Краткая DNS-пропагация возможна.
4. Проверить HTTPS именно gamescout.online, SHA, JS/CSS, три мира, auth/me, рейтинг, noindex, 404 и доверенный ingress IP. Не включать регистрацию, боевые платежи или схемные миграции.
5. При неуспехе вернуть точную исходную DNS/custom-domain конфигурацию. Только после принятия переключения адаптировать deploy postflight к фактическому Яндекс-источнику; не требовать активного Cloudflare custom domain от Яндекс-публикации.

Это план обратимого переключения, не выполненное изменение DNS. Автоматическая прокладка приватных сессий через Cloudflare не выбрана: она меняет утверждённую границу персональных данных.
