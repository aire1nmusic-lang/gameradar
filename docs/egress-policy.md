# Outbound policy v1

Согласовано 30.09.2026: единый private API, бесплатные checks, event-driven Sonnet позже. Никакой автономии production deploy.

`private-api/egress.mjs` — начало центральной политики, не утверждение, что любой существующий outbound уже проверен. Raw nickname/copyright inference полностью выключен даже при установленном OpenRouter key. `reviewNickname` оставляет сомнительный ник REVIEW/«Анонимно»; локально запрещенный — ANONYMOUS. Ledger/Coins/Support сохраняются. `analyzeCopyright` проверяет только presence локально; complete => DOUBTFUL/human review БЕЗ automatic restriction, incomplete => INCOMPLETE. Intake проверяет target; scoped restriction/restore по решению администратора и PG outbox остаются. Это не AI и не установление авторства/законности. Для совместимости полного case сохраняется legacy status PENDING_AI, но local job завершен и ai_reason прямо говорит о ручной проверке до ограничения; это не работающий AI provider. Audit использует copyright.local_triage. Когда будет нужна новая отдельная human-review status модель, делать additive migration и UI labels, не считать ее уже внедренной.

Maintenance обрабатывает эти локальные очереди без OpenRouter credentials с model marker `local-policy-v1`. После трех ошибок review callback очередь не вызывает callback снова; nickname идет REVIEW, copyright остается в приватной admin очереди с analysis_exhausted. Администратор может разрешить кейс вручную. Crash после последнего lease тоже прекращает новые попытки; требуется ручная проверка.

Telegram на delivery пересоздает сообщение из фиксированного event template и внутреннего random event ID. Содержимое старого outbox.message не отправляется; неизвестный event отвергается. Bot token и chat ID — отдельные transport credentials/recipient, никогда не model data. Первоначально notifications-only: approval/callback actions не реализованы. Event ID соответствует gs_telegram_outbox.id в RU базе; claim/evidence/user/server детали только в ADMIN/RU.

Каждый следующий внешний AI/monitoring connector должен использовать отдельно одобренную strict schema без unknown fields и свободного private текста. Запрещены arbitrary fetch/SQL/tools, cookies, IP/device, credentials, raw bodies/logs, evidence/identity. Regex не доказывает обезличивание. Ник с настоящим именем/opaque stable user ID может оставаться ПДн. OpenRouter usage/balance read — отдельный существующий connector, не inference; secrets не отдавать модели. Email/OAuth/Robokassa нужны свои explicit purpose/recipient policies и юридическая проверка.

Остались независимые задачи: public projection free facts/URLs и public relay query allowlist; transactional connectors; incident DTO/cost caps/privacy routing; live Telegram. Не представлять v1 как сетевой firewall: сторонний код с raw fetch может обойти библиотеку; code review/test policy обязательны. Для реального сетевого enforcement понадобится отдельно спроектированный egress proxy, сейчас его не создаем.

Проверка: test:private и synthetic egress tests, no paid inference. Изменения без миграций. Откат к raw inference НЕ безопасный default: при rollback выключить OpenRouter nickname/copyright configs либо оставить privacy patch; не развертывать старый unsafe connector с живыми ключами.
