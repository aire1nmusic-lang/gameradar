# Local three-game acceptance (no production writes)

This run uses the existing development D1 and PGlite databases. Keep `--remote`, real Robokassa checkout and production DNS out of it. The 70 confirmed L2/Minecraft/GTA RP cards are public facts from the curated dataset; online remains unknown until an actual probe succeeds. The nine DEMO cards can coexist for clearly labelled fixtures.

1. Start the local D1 Worker on `127.0.0.1:8787` and apply pending **local** D1 migrations (`npm run db:migrate`). Set `XDG_CONFIG_HOME` to a writable workspace directory on Windows if Wrangler cannot write its default profile.
2. Check and import only core games: `npm run import:check`, then `npm run import:servers -- --games lineage2,minecraft,gtarp`. The importer is idempotent and leaves Rust/CS2/DayZ untouched. Do not use `--remote` in this acceptance run.
3. Stop the local private API before running `node private-api/import-catalog.mjs`, which imports the published public cards into **local** PGlite for votes, Claim and Support. Restart the private API afterward.
4. To verify real local outbox delivery, create a random 32-byte test secret in ignored `output/private-core/`. Pass the same value to Wrangler as `--var PUBLIC_PROJECTION_SECRET:<secret>` and to the local private API as `LOCAL_PUBLIC_PROJECTION_SECRET`. The private API fixes its development destination to `http://127.0.0.1:8787/api/internal/public-projection`; it cannot send these local events to an arbitrary URL. The secret is a local fixture, never a production credential.
5. Start `npm run dev:core-ui`. With disposable, confirmed local accounts, exercise the three published cards and check `/admin` → События: `projection.pending` should return to zero, and any lag alert should recover. Compare the public `support` aggregate on the same three card IDs in the Worker HTTP response. The local «Начислить 10 тестовых Coins» control writes a labelled fixture ledger row; it is not a purchase.
6. Run `npm run build:catalog -- http://127.0.0.1:8787`. It captures only published non-DEMO public facts and must report zero reconciliation issues. Serve `dist` through local Cloudflare Pages, then run `SEO_BASE_URL=http://127.0.0.1:4180 npm run test:seo` with `GS_SEO_SNAPSHOT_FILE=output/seo-public-snapshot.json` to check actual HTTP, including the unknown-route 404.

This is a local acceptance exercise. Yandex PostgreSQL/container/gateway, production D1 routing, live email/OAuth, Turnstile, OpenRouter, Telegram and Robokassa test credentials require separate staging verification. Never interpret local DEMO Claim approval or fixture Coins as real ownership or a real payment.
