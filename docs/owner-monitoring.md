# Claim-scoped online target

An email-confirmed owner with an approved Claim can set one public probe target for their server in `/account`. Minecraft accepts a public hostname and optional port for Server List Ping; L2 accepts a public login-server hostname and port, which cannot provide a player count; GTA RP accepts a bare public HTTP(S) FiveM origin. AGENT tokens and arbitrary headers are excluded. The private API and public Worker both reject private/reserved network targets, URL credentials, fragments, wrong-game methods and FiveM relay hosts. The Worker resolves and pins public DNS at probe time, refuses redirects and bounds response size and time.

Migration `018_owner_monitoring.sql` keeps owner configuration, user identity and audit in PostgreSQL. The authoritative private transaction changes the target, increments the server version and appends a public snapshot to the retrying outbox. D1 receives only the public, token-free endpoint or an `enabled:false` switch. A version-gated D1 batch updates `monitoring_targets` and clears the previous online count until the next successful probe. A replay of an older version cannot restore a retired endpoint. An identical owner request creates no new outbox entry or audit event. The importer respects the projected Claim bit and cannot replace this target on a claimed card.

Rollout order for staging: migrate PostgreSQL through 018 with the reviewed fingerprint and verified backup; deploy the public Worker parser before the private writer; deploy the private API and allow signed outbox delivery; confirm D1 target/version, observe at least two real checks with source and timestamps, test disable, and review lag/alerts. Local PGlite/SQLite tests and the isolated Worker monitor acceptance are evidence only, not a deployed check. No production migration, queue change, DNS change or resource creation is authorized by this runbook.

Rollback: stop owner target writes, retain the private row/audit/outbox, and submit a later disable or corrected target through the owner API. Let its newer snapshot reach D1 and verify that an old count is hidden. Preserve sample history as observations from their original source. Do not mutate private ownership or manually decrement a projection version.
